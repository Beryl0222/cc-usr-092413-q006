# 公共健身资产问效

服务用于连接公益资金、健身设施、使用情况和维护责任，为后续建设决策提供可核验依据。
在基础服务之上，现已补充**设施退役与替换决策链**，回答年度预算评审中提出的问题：
反复维修但使用率下降、高使用设施因零件停产长期停用的设施如何决策，资金为何继续投入、
何时停止，以及居民服务是否得到补位。

## 决策链规则

- **证据按时间汇总**：资金来源、安装批次、使用证据、安全事件、维修成本、服务覆盖六类
  证据进入同一时间线。使用证据**缺测显式标注为 `no_evidence`，绝不折算为零使用**；
  观测到的 0 次使用与缺测严格区分。
- **四方会签**：运营单位提出保留 / 迁移 / 改造 / 退役方案（含旧资产与二维码指导去向）；
  财务核对未摊销资金及处置；安全负责人确认风险；**社区代表只可对服务缺口签署意见**，
  越权字段直接拒绝。全部满足后才形成带生效日的决定。
- **退役**：关闭全部未结与未来工单，但事故与支出历史原样保留。
- **替换交接（原子）**：新资产一次性承接适用的场地义务、缓存通知（自动改投新资产）与
  保修责任；旧故障、旧事故、旧支出明确排除，不能算到新资产台账。任一条目校验失败则
  整笔交接回滚。
- **预算排序**：仅接受已批准（含版本号）的公共价值规则；缺测指标从中性归一化中剔除
  而非按零计分；预算按顺位分配，人工调整必须书面说明理由并留痕。
- **回执幂等**：现场动作携带 `receipt_id`，重复回执返回首次结果，不重复处置。
- **撤回与分期可恢复**：决定可撤回，已执行的关单 / 交接 / 分期作为历史保留；按原方案
  恢复时会签仍有效，方案实质变更需重新会签。
- **资金可追溯**：`funding-trace` 对每笔资金说明继续投入理由、停止界点（退役生效日）、
  未摊销资金处置，以及替换 / 保留是否已补位居民服务。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 服务身份 |
| POST | `/cases` | 建立设施案件（一设施一案件） |
| POST | `/cases/{id}/evidence` | 追加六类证据记录 |
| GET | `/cases/{id}/timeline` | 按时间/类型汇总的证据视图 |
| GET | `/cases/{id}` | 案件、提案、会签、决定与执行状态 |
| POST | `/proposals` | 运营单位提交保留/迁移/改造/退役方案 |
| POST | `/signoffs` | finance / safety / community 会签 |
| POST | `/decisions` | 会签齐备后形成带生效日的决定 |
| POST | `/decisions/withdraw` | 撤回决定（保留已执行历史，可恢复） |
| POST | `/phases/plan`、`/phases/complete` | 分期计划与分期完成回执 |
| POST | `/retirements` | 执行退役（关工单、保历史、处置二维码） |
| POST | `/handovers` | 替换设备原子交接 |
| POST | `/assets/{id}/records` | 新资产投用后的自身维修/事故登记 |
| GET | `/assets/{id}` | 新资产台账（不含旧资产历史） |
| POST | `/budget/order`、`/budget/adjust` | 公共价值排序与带理由的人工调整 |
| GET | `/facilities/{id}/funding-trace` | 资金继续/停止与服务补位追溯 |

领域逻辑全部在标准库实现的 `domain.py`（`DecisionStore`，内存态、线程安全）中，
`service.py` 仅负责 HTTP 编解码与路由。

## 运行

```bash
python3 service.py --check          # 核对服务配置
python3 service.py --port 8000      # 启动后访问 /health
```

## 测试与构建

执行完整测试（29 项领域规则 + 6 项 HTTP 合同）：

```bash
npm test
```

执行编译检查：

```bash
python3 -m compileall -q .
```

两条命令都可在单个 Linux 应用容器内直接运行，不需要额外服务。
